# Sources — Glossary

*Where the outside-world facts in the [Glossary](../Glossary.md) came from. The Glossary carries each fact's label in place; this file carries the citation behind it, and what it does not cover.*

- **The Blender concepts — Scene, Frame, View layer, the render atom, and Output.** How a `.blend` holds several scenes; how view layers sit under a scene and render per frame; that a view layer's renderability is animatable; that a frame may resolve to zero, one, or many rendered pieces; and that a frame's outputs land on disk only once every view layer active on it has finished. Source: the Creator, a Blender professional. Label: **Creator-stated** (2026-07-24).

  What this does not cover, two things. First, the Creator has stated these facts do **not** need confirming against Blender's official documentation — they are settled on the Creator's authority under Rule 2, and are deliberately *not* parked for Blender Research the way the frame questions in [Open Threads](../Open%20Threads.md) are. A later Blender Research agent should leave them settled, not re-open them. Second, they fix only the concepts and how they relate — not how Smoozy lets the user drive them. Choosing a scene, setting a frame range, and the rest are Smoozy decisions owned by the Render Settings spec, not facts sourced here.

  The name **Renderlet** is not a sourced fact and has no citation: it is a Smoozy naming decision, recorded by its Creator-stated label in the Glossary. It appears here only to note that Blender itself has no single word for the unit.

- **Dependency.** That a `.blend` points at things it needs rather than holding them. Source: the Creator, a Blender professional. Label: **Creator-stated** (2026-07-28). Only the term is fixed here. Which kinds exist — and everything open about them, including that the Creator's own list is deliberately incomplete — is owned and cited by the [Dependency Upload & Remap sources](../../Specs/Sources/Dependency%20Upload%20&%20Remap.sources.md), so nobody should add a second citation for it here.

- **The compositor terms — Regular output path, Compositor, and File output node.** That a scene carries one output path of its own, quite separate from the compositor; that the compositor can be switched off and that what switches it has moved between Blender versions; and that a file output node writes files of its own to anywhere it is told, carrying any number of named outputs, with several nodes able to feed from the same place. Source: the Creator, a Blender professional. Label: **Creator-stated** (2026-07-28).

  These stand differently from the five above. The Creator has asked that **all three be confirmed at Blender Research**, and with more rigour than anything else in the project, because the file output node's behaviour changes from version to version. Treat them as good enough to plan on and expected to be checked. The full set of open questions behind them, and which of them are unresolved rather than Creator-stated, lives in the [What a job writes sources](../../Specs/Sources/What%20a%20job%20writes.sources.md); only the names are fixed here.

- **The passes — beauty, utility, and diffuse colour.** Owned by the [Queue & History sources](../../Specs/Sources/Queue%20&%20History.sources.md), which carries the label and the citation for the beauty-and-utility distinction; the [What a job writes sources](../../Specs/Sources/What%20a%20job%20writes.sources.md) carries the diffuse colour pass. They are listed here so nobody adds a second citation for them: the reason the compositor terms above must be checked — a node whose behaviour changes between versions — does not apply to the passes, and they are not to be swept up with them.

- **The names under Jobs** — Main output, Working format, Viewing format — are not sourced facts and have no citation: they are Smoozy naming decisions, like Renderlet. What they name belongs to a job rather than to Blender, which is why they sit outside the Blender section. One outside fact sits under them, that some image formats hold more light than a screen can show, and it is cited in the [What a job writes sources](../../Specs/Sources/What%20a%20job%20writes.sources.md).
