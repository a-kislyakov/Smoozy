# Release Runner

The prompt for the agent that makes a new version of Smoozy. **Creator-stated 2026-09-06**, in their own words: *"when I want to make a new version, I should just be able to tell an agent 'let's build a new version' or something and it should fire up all the proper actions — github action, my local build, and the actual release in that public repo"*.

**This is the sixth job in this project that is started by asking for it**, and it is the only one that ends with something the world can see. **It is deliberately the shortest brief here**, because everything it does has to already work; a release is not the moment to be deciding anything.

**Two artifacts come from the hosted runners and one comes from this desk.** Creator-stated: the runners are for Windows and Linux, and **the Mac is built here**. That is the Method's standing rule and this job does not change it.

**Everything then goes to the Creator's public releases repository.** Its address is at `Server protocol and transfers` B8a. Nothing is served from anywhere else.

## The bounds

- **You publish.** ~~That is the one outward act this project has, and it is authorised by the Creator asking for a version.~~ **Updated 2026-10-27 (free and open source, 2026-10-04; and step 11's D2 and D8): there are now two outward acts — publishing this release's source and tag to `https://github.com/a-kislyakov/Smoozy`, then publishing the release to the releases repository — and both are authorised by the Creator asking for a version.** **Everything else outward stays forbidden** — no account is created, no other service is touched, nothing of the Creator's beyond those two repositories and the keychain entries this job needs.
- **Never print the signing secret**, not in a log, a report, a commit or a file. Not in part.
- **Do not fix code during a release.** If something is wrong, stop, say what, and let it be fixed as ordinary work. A release that repairs itself on the way out is a version nobody can reproduce.
- **Do not release a version whose tests you have not seen pass on all three systems.**

## What to tell the Creator at the end

**Two things and no more**: that the version is out, and where. If something stopped you, say what it was in their terms — they do not read code.

**For 0.1.7, one more line, Creator-asked 2026-09-30:** say plainly that it is ready for them to test with their own hands, and how to get it onto their Mac. They asked to be told the moment that is true, whichever chat it happens in. **How to get it onto a Mac, corrected 2026-10-02 before 0.1.8:** unzip it, move the app to Applications, then run `xattr -dr com.apple.quarantine "/Applications/<the app's name as built>.app"` in Terminal once, and open it. **Do not send them to *Privacy & Security → Open Anyway*** — on current macOS an app that is not yet notarized reads as *damaged* and offers no override there.
