- **A file is built up in place at its own final name.** No file under another name appears first and nothing is renamed, in all four versions on both machines. So there is no temporary name to key on.

Answer: **Section 7 E1–E5**. **The ending is a sequence rather than a judgement**: the ending arrives from `Queue & History`, named as one of the four, live or at catch-up; **one ending walk** runs, after which every narrowed entry present and not zero bytes is fetchable and every one absent or zero-byte becomes *never coming*; the fetch queue drains to terminal states; **and the arrangement is done when every unit is terminal**, the reading then saying **ended**, with arrivals against the whole, short where short and never *complete* — **and where a switch-on has reset the destination part-way through, that reading names both folders. Done is not for ever**: a new render-start for the same job re-arms the arrangement, its *never coming* entries re-opening to *owed* for the frames the new attempt's list names, the whole recomputed, the walks resumed, and the sequence run again to a second done — while what is *fetched* stays fetched, so a re-run never arrives over a file the user already has. **In the interval the reading says the job has ended and files are still coming home.** A job that ended badly runs the same two steps, and the emptied frames of a machine that went down land as zero-byte *never coming* entries whose shortfall the count says. **And where the ending is *stopped*, *failed* or *given up*, the entries of the frame that was in flight are fetched and marked *fetched, could not be vouched for*, named on the arrangement's existing telling surface** — the one file most likely to be torn is the one nothing else here would say anything about, since it arrived, so the count is not short and there is no saved line for it. **Two things end an arrangement with no ending ever arriving** — a removed server, permanently, and a cancelled job — **and one merely strands it truthfully**: a machine whose installation is gone has no job record left to end, so the arrangement idles and ends by the user's own act, and nothing pretends an ending that never happened.
