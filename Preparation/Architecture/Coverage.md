## How to read this file

**A row is a promise a spec or a design document makes that this stage has to answer.** It holds the promise **quoted** — not described — which document it came from, which facts it waits on, the constraints its answer must honour, and where its answer is. Quoted is the point: the coverage gate finds a row's promise by searching the source document for that exact string, so an answer to a promise somebody misread is invisible unless the promise sits on the page beside it.

**Where the answer is** means the sentences that keep the promise, clause by clause where the promise has clauses — never just the document holding them. That is what lets the gate be a matching exercise rather than a judgment.

**A row takes a number and keeps it for good.** Never reused, never renumbered. A row that turns out to be wrong, or to belong to Build, keeps its number with a note saying so rather than vanishing and taking the count down with it.

**A fact takes a number and keeps it for good too.** One fact serves several promises, so it needs a name of its own that a row and a spec's sources file can both point at.

**Constraints live here rather than in the sweep trail**, because everything under `Audits/` is outside this stage's reading and an answering agent must never have to open it. A sweep file records how a row was found; this file records what the answer has to honour.

**A quoted promise carries its source document's links, and those links will not resolve from the rows file. Leave them broken.** A promise quoted out of a spec brings the spec's own relative paths with it, and the rows files sit at a different depth, so a link checker flags them. **Repointing them would change the quoted string, and the coverage gate finds a row's promise by searching the source document for that exact string** — so tidying the links breaks the gate. The quote is evidence, not navigation.
**That rule is the rows files' and does not reach an answer document. Added 2026-08-23, out of a case.** From a rows file a spec's own relative link is dead, which is harmless. **From `Preparation/Architecture/` the same link resolves — to the architecture document of that name rather than to the spec** — which is a live pointer at the wrong document sitting inside a quoted promise. So an answer document does not carry the markup. **Nor does it quietly write the link's words as plain text**, which leaves a quotation that can never match and a gate failure raised again every pass. **It replaces the whole parenthesis with a marked elision**, so the quote becomes fragments that each match exactly.

**Only the architecture runner writes this file.** A sweep agent hands its rows back in its own file under `Audits/Architecture/Sweep/`; the runner numbers them and merges them here.

The [Method](Method.md) owns what earns a row, in what order rows are answered, and how the whole thing is checked.
