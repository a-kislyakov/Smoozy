## S31 — that the transport's compression is off by default, and what its own manual says it is worth

Added 2026-08-31 for Row 514, with [S31](../Server%20protocol%20and%20transfers.md#77-what-a-transfer-does-not-do-on-its-own-which-is-the-answer-to-the-second-clause). Label: **documented**.

**Source:** OpenSSH's own manual pages, as shipped in the operating system on the Creator's Mac and read there on **2026-08-31** — OpenSSH_10.3p1, macOS 26.6, the pages dated **March 23, 2026**. Three entries, quoted in full where they are short:

- `ssh_config(5)`, `Compression`: *"Specifies whether to use compression. The argument must be yes or no (the default)."*
- `sshd_config(5)`, `Compression`: *"Specifies whether compression is enabled after the user has authenticated successfully. The argument must be yes, delayed (a legacy synonym for yes) or no. The default is yes."*
- `ssh(1)`, `-C`: *"Requests compression of all data (including stdin, stdout, stderr, and data for forwarded X11, TCP and UNIX-domain connections). The compression algorithm is the same used by gzip(1). Compression is desirable on modem lines and other slow connections, but will only slow down things on fast networks."*

**This is the same route [Section 1.1](../Server%20protocol%20and%20transfers.md#11-what-the-surface-is-made-of-and-it-is-two-mechanisms-rather-than-one) and [S11](../Server%20protocol%20and%20transfers.md#74-resume-never-trusts-a-partial-it-has-not-verified) already take** — the transport's own manual as installed, which is where this document's `sftp(1)` quotations come from too.

**What it covers:** the client default, that the far end permits compression after authentication, and the publication's own statement of when compression helps and when it does not. **What it does not cover:** any measurement on any line this project has used — no compression ratio, no throughput comparison, and no reading on a rented machine. **Nothing rests on one:** S31's decision is the default plus the publication's own advice, and the file-body half of S31 is a requirement about resume offsets rather than a claim about the world.

**What breaks if the reading is wrong:** nothing. A transfer that compresses nothing is correct and possibly slower, and every promise about wholeness and carrying on holds either way. **What would break if the file body were compressed instead** is written in S31 and is the reason that half is a requirement rather than a preference.
